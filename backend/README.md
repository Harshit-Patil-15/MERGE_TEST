# Hackathon Backend Boilerplate (TypeScript)

A production-ready, highly-scalable, and secure Node.js & Express.js starter template for MERN hackathons. It uses TypeScript, ES Modules (import/export), is pre-configured with MongoDB (Mongoose), Socket.io, JWT Authentication, and follows Clean Architecture patterns to help you start writing feature code instantly.

---

## Features

- **TypeScript Core**: Full type definitions, interfaces, and strict compiler checks out of the box.
- **ES Modules**: Modern JavaScript syntax (`import`/`export`) ready.
- **JWT Auth**: Full registration, login, logout, and protected route middlewares (supporting header credentials and cookies).
- **Socket.io Integration**: Configured socket handler supporting room join/leave protocols and chat messaging out-of-the-box.
- **Security Primitives**:
  - `helmet` for HTTP headers security.
  - `cors` enabled with configurable origins.
  - `express-validator` setup for strict input asserts.
  - `bcryptjs` for secure password hashing.
  - `cookie-parser` to securely read browser cookies.
- **Robust Error Handling**: Global error catching middleware translating database/JWT failures into a standardized JSON response structure.
- **Multer Pre-setup**: File upload utility supporting disk storage (`./uploads`) and memory storage (for Cloudinary, AWS S3, etc.).
- **Generic CRUD Task Module**: Fully working templates (Model, Controller, Routes, Validation) to clone and adapt.
- **Health check**: Operational systems health check endpoint (`/api/health`).

## Environment Variables

Create a `.env` file in the root directory (based on `.env.example`):

| Variable | Description | Default |
|----------|-------------|---------|
| `PORT` | Local server port | `5000` |
| `NODE_ENV` | Mode of runtime ecosystem (`development`/`production`) | `development` |
| `MONGO_URI` | MongoDB Connection URL | *Required* |
| `JWT_SECRET` | Secret key for JWT hashing encryption | *Required* |
| `JWT_EXPIRES_IN` | JWT longevity span | `7d` |
| `CLIENT_URL` | Cross-Origin allowed domain (Frontend URL) | `http://localhost:3000` |

## Installation & Setup

1. **Clone & Navigate:**
   ```bash
   cd backend
   ```

2. **Install Dependencies:**
   ```bash
   npm install
   ```

3. **Configure Environment:**
   Copy `.env.example` to `.env` and fill in your connection strings:
   ```bash
   cp .env.example .env
   ```

4. **Run the Server:**
   * **Development (auto-reload via tsx compiling source files on changes):**
     ```bash
     npm run dev
     ```
   * **Build Production version:**
     ```bash
     npm run build
     ```
   * **Start Built Production version (runs compiled JS inside dist/):**
     ```bash
     npm start
     ```

## Standard JSON Response Formats

All routes speak consistent JSON payloads under these schemas:

### Success Response (HTTP 2xx)
```json
{
  "success": true,
  "message": "Operation successful description",
  "data": { ... }
}
```

### Error Response (HTTP 4xx / 5xx)
```json
{
  "success": false,
  "message": "Failure summary explanation",
  "errors": [
    "Detailed validation message 1",
    "Detailed validation message 2"
  ]
}
```

## API Endpoints

### 🩺 Health Diagnostics
* **`GET /api/health`** (Public) - System stats, database connectivity, node metadata.

### 🔐 Authentication (`/api/auth`)
* **`POST /register`** (Public) - Create user account. Returns auth cookie token + user object.
  - Body: `{ "name": "user", "email": "test@test.com", "password": "password123", "role": "user" }`
* **`POST /login`** (Public) - Authenticate credentials. Returns auth cookie token + user.
  - Body: `{ "email": "test@test.com", "password": "password123" }`
* **`POST /logout`** (Protected) - Clears authentication cookie token.
* **`GET /me`** (Protected) - Retrieves details of currently logged-in user.

### 📋 Sample Task CRUD (`/api/tasks`)
All task endpoints require authentication (`Authorization: Bearer <token>` or HTTP cookie).

* **`GET /`** - Retrieve array of logged-in user's tasks. (Accepts optional `?status=pending` and `?priority=high` filters).
* **`POST /`** - Create new task.
  - Body: `{ "title": "Hackathon MVP", "description": "Finish backend boiler", "status": "in-progress", "priority": "high" }`
* **`GET /:id`** - Get single task by MongoDB ID. (Verifies ownership).
* **`PUT /:id`** - Update specific fields of a task.
  - Body: `{ "status": "completed" }`
* **`DELETE /:id`** - Delete target task from system database.

## Socket.io Specifications (WebSockets)

Connect to the server URL (same as backend server e.g. `http://localhost:5000`).

### Handlers & Client Listeners

#### 🔽 Listening Events (Client-side listeners)
- **`receive-message`**: Triggers when a chat message is relative to the joined room.
  - Payload: `{ roomId, message, sender, timestamp }`
- **`sys-message`**: Triggers when a custom client actions joins or leaves.
  - Payload: `{ message }`

#### 🔼 Emit Events (Client-side triggers)
- **`join-room`**: Subscribes client to a custom chat/channel identifier.
  - Parameter: `roomId` (String)
- **`leave-room`**: Unsubscribes client from a target Room.
  - Parameter: `roomId` (String)
- **`send-message`**: Broadcaster of message payloads to room occupants.
  - Parameters: `{ roomId, message, sender }`
